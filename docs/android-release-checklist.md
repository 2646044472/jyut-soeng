# 粤常 Android 发布验收与故障记录

## 发布顺序

1. 在独立候选分支跑 CI，不改主分支、不先打正式 tag。记录候选提交、版本和预期精校张数。
2. 数据校验与单元测试通过后，构建签名 APK。对照上一个正式 APK 检查应用包名、签名证书、版本号和离线包，不能用「能编译」代替「能覆盖安装」。
3. 在空白、离线的 CI 模拟器验两遍：新安装从首页学到第一张未学精校卡，真实点击「下一句」进入下一张并有数据库记录；旧版学一张后执行覆盖安装，核对旧 SRS 与记录逐值保留，接着优先学未学精校卡。不要在用户手机上执行清库脚本。
4. 只有候选验证 job 全绿并有 APK／内容包时才给同一提交打正式 tag。确认 Release 里实际能下载，再报发布完成。源代码已推、测试中打印了 Pass、APK 已构建与正式发布是四个不同状态。签名资料与模拟器数据不入产物。
